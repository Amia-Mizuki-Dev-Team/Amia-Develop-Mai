# 01 · 协议体系总览

本文是舞萌（maimai DX）国服协议文档的总纲，先建立整体认知，再进入各专题。

## 一、三通道架构

舞萌街机生态涉及三类彼此独立的通信通道，各自有独立的加密体系与服务器：

```
                          ┌─────────────────────────────┐
                          │         官方服务器群          │
                          │                             │
        ┌─────────────────┤  A. 业务API（游戏数据Servlet）│
        │                 │  B. 鉴权库                    │
        │                 │  C. 更新分发（ALL.Net）       │
        │                 └──────────┬──────────┬───────┘
        │                            │          │
┌───────┴────────┐          ┌────────┴───┐  ┌───┴────────────┐
│     街机机台     │          │  玩家手机端  │  │  社区查分平台    │
│ (游戏客户端本体)  │          │ (二维码来源)  │  │ (落雪/水鱼等)    │
└────────────────┘          └────────────┘  └────────────────┘
```

### A. 业务 API 通道（游戏数据 Servlet）

- 用途：玩家数据读写——登录/登出、成绩上传、物品/乐曲/地图/票务等全量数据同步
- 特征：请求体经 `JSON → zlib → PKCS7 → AES-256-CBC` 加密；URL 路径由接口名哈希得出（详见 02）
- 鉴权：机台 keychip + 玩家二维码换取 userID/token（详见 03）
- 端点：数十个业务接口，按会话阶段分为若干类别（概念见 04-会话生命周期）；随版本迭代曾出现新旧两代加密参数（详见 05）

### B. 鉴权库通道

- 用途：二维码 → 玩家身份（userID + token）的兑换
- 特征：独立于业务 API 的明文 JSON 接口，请求以 SHA-256 签名校验机台身份
- 定位：业务 API 会话的"入场券"来源

### C. 更新分发通道（ALL.Net）

- 用途：向机台下发更新指示书、更新包（游戏数据包/程序包）
- 特征：独立的 LITE 认证加密（AES-CBC + 随机前缀）、key=value 指示书、INI 配置、断点续传下载、专用解密工具（详见 09）
- 产物：解密后的更新包即为游戏静态数据（乐曲、角色、万花筒等 XML）

### D. 第三方社区平台

- 落雪（LXNS）、水鱼（diving-fish）等社区查分平台，提供 OAuth 授权与成绩上传/查询 API（详见 10）
- 与官方通道无关，是逆向工具链的下游消费方

## 二、两代加密体系

业务 API 通道的加密参数随客户端版本迭代，目前观察到两个代际：

| 代际 | 请求头 Mai-Encoding | 客户端版本标识 | 说明 |
|---|---|---|---|
| 旧代（1.53 组） | `1.53` | 1.53 / 1053000 | 较早版本机台使用的参数组 |
| 新代（1.55/1.56 组） | `1.55` | 1.55 / 155 | 新版本机台使用的参数组，两代结构相同仅参数不同 |

- 两代**算法与流程完全一致**，差异仅在 AES 密钥/IV 与端点混淆参数（值均不公开，详见 08）
- 鉴权库通道的签名盐跨代共用

## 三、生态关系

```
官方更新分发 ──解密──► 游戏静态数据(XML) ──► 曲库/定数/谱面信息
                                              │
官方业务 API ◄──协议实现── 逆向工具链（插件/脚本）──► 社区查分平台
     ▲                            │
     └── 机台凭据(keychip) ◄───────┘
```

- **上游**：更新分发通道解出的静态数据（乐曲、谱面、定数等）是下游一切业务逻辑的数据基础
- **中游**：业务 API 协议实现（机台模拟客户端），承担"拉取玩家数据 / 上传成绩 / 解锁物品"等操作
- **下游**：社区查分平台与展示层（成绩展示、Rating 计算、教学分析）

## 四、命名约定

- 国服业务接口名称统一带有固定的国服标识后缀，参与端点哈希计算（详见 02）；具体接口名称属隐私，不公开
- 客户端标识：机台端以 `keychip`（机台芯片 ID）标识；玩家侧以玩家编号标识
- 鉴权请求中的游戏标识固定为"舞萌 DX"
