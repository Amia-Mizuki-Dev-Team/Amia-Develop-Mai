# 07 · 核心算法

本文描述协议中的关键算法：伪随机数生成、达成率与等级判定、DX 分计算、称号体系。

## 一、伪随机数（playSpecial 位反转算法）

游玩记录中存在一个"特技随机数"字段，其生成算法为固定结构的伪随机：

```
输入: 无
1. 取随机数 r ∈ [1, 1037933]
2. n = r × 2069 + 1024
3. 对 n 做 32 次位反转:
      result = 0
      重复 32 次:
        result = (result << 1) + (n & 1)
        n = n >> 1
4. 若 result > 0x7FFFFFFF: result -= 0x100000000   # 转为有符号 32 位
输出: result
```

即：先线性变换，再逐位镜像反转（bit-reverse），最后做有符号 32 位归一。

## 三、达成率计算（判定权重）

达成率由五类键位的判定计数加权得出，各键位单 note 权重：

| 判定 | tap/hold/slide/touch | break |
|---|---|---|
| CriticalPerfect | 10000 | 12500 |
| Perfect | 10000 | 12500 |
| Great | 8000 | 10000 |
| Good | 5000 | 6250 |
| Miss | 0 | 0 |

另：break 的 CriticalPerfect 每 note 附加 100 点加成。

```
基础分 = Σ(tap/hold/slide/touch: CP+P×10000 + G×8000 + Gd×5000)
       + Σ(break: CP+P×12500 + G×10000 + Gd×6250)
加成   = break_CP × 100
满分   = (tap+hold+slide+touch) × 10000 + break × 12500 + break × 100
达成率 = (基础分 + 加成) × 1000000 / 满分
```

## 四、DX 分计算（deluxscore）

DX 分同样由判定计数线性加权，单 note 权重：

```
DX分 = (tap+hold+slide+touch+break 的 CriticalPerfect) × 3
     + (              Perfect           ) × 2
     + (              Great             ) × 1
```

Good 与 Miss 不得分。

## 五、称号体系（BADGE）

生成目标成绩时按称号约束达成率区间与 combo/sync 状态：

| 称号 | 达成率区间 | comboStatus 要求 | syncStatus 要求 |
|---|---|---|---|
| 霸者 | 800000 ~ 899999 | 无 | 无 |
| 極 | 1000000 ~ 1005000 | ≥ 2（FC+） | 无 |
| 将 | 1000000 ~ 1005000 | 无 | 无 |
| 神 | 1005000 ~ 1010000 | ≥ 3（AP） | 无 |
| 舞舞 | 1000000 ~ 1005000 | ≥ 3（AP） | ≥ 3（同步） |

## 六、判定计数生成（模拟实现）

逆向协议实现需要构造"合法"的判定计数时，采用如下策略：

1. 按曲目谱面的各键位总 note 数（tap/hold/slide/touch/break），逐档随机分配计数直至总和等于该键位总 note 数
2. 由计数计算达成率，检查是否落入目标称号区间；不满足则重新随机（重试上限后取区间下限）
3. combo 状态按称号要求设置，maxCombo 取谱面总 note 数
4. FAST/LATE 计数、生命值等字段按固定模式填充

> 该策略仅用于协议层面的数据结构研究说明，本文档不提供任何可运行的生成实现。
