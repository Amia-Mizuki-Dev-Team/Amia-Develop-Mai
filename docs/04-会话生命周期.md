# 04 · 会话生命周期

本文以抽象概念描述一次完整的业务会话流程。具体接口名称与字段级构造细节属隐私信息，不在公开范围内。

## 一、会话阶段总览

```
机台初始化（机台级请求）
  连通探测 → 机台设置上报 → 机台状态上报 → 游戏内容预取
      ↓
玩家入场
  二维码鉴权（鉴权库）→ 获得玩家身份凭证
      ↓
登录前预检
  占用检查 + 加密代际探测
      ↓
建立会话
  登录（支持"续关"模式）→ 获得会话编号
      ↓
数据拉取
  单次类数据 → 游标分页类数据
      ↓
数据写入（可选）
  全量同步 / 游玩记录 / 票务
      ↓
续关（批量场景，可选）
  在同一会话中再次发起登录继续处理
      ↓
登出
  登出请求（含会话性能统计）→ 释放占用
```

## 二、机台初始化阶段

机台级请求以机台身份（keychip）标识，依次完成：

1. **连通探测**：确认与业务通道的连通性
2. **机台设置上报**：门店、区域、ROM 版本、机台世代等信息
3. **机台状态上报**：轨道配置（单机/多机）等测试模式状态
4. **游戏内容预取**：活动、票务商品、排行、禁用乐曲、屏蔽词、周常活动等机台级内容

初始化阶段的产物包括**禁用乐曲列表**与**屏蔽词表**，供后续流程过滤使用。

## 三、登录前预检

正式登录前先做一次预检，作用有二：

1. **占用检查**：若玩家已处于登录状态，说明其正在其他机台游玩，必须先登出才能继续
2. **版本探测**：读取玩家数据中的客户端版本字段，选择对应的加密代际（见 05）

预检响应还包含玩家名称、Rating、封禁状态等概要信息。

## 四、建立会话

- 登录成功后，服务端返回**会话编号**与上次登录日期等概要信息
- 会话支持**续关模式**：批量处理场景中，一次会话完成一批操作后再次发起登录以继续下一批，避免长时间占用单一会话

## 五、数据拉取

按响应形态分为两类：

| 类型 | 特征 |
|---|---|
| 单次类 | 一次请求返回完整数据（基础档案、设置、Rating、活动、任务等） |
| 游标分页类 | 以"游标 + 每页条数"分页，响应返回下一页游标，游标归零表示结束；物品类数据按类目分段遍历 |

## 六、数据写入

写入场景包括**全量同步、游玩记录、票务**三类。协议实现观察到一个经验性约束：写入类操作与登出之间通常保持约 60 秒间隔（疑似服务端会话节流窗口）。

## 七、登出

- 登出请求区分**正常/异常**等类型，异常路径以异常类型登出以释放占用
- **会话性能统计**：登出时客户端随请求上报本次会话的接口调用统计（次数、字节量、耗时、重试次数等）
- **登出为单次请求**：登出失败（返回非成功或连接异常）时，可由实现侧重试，以降低"假登录占用"（玩家被卡在已登录状态）的概率

## 八、异常路径

- 预检发现玩家已登录 → 拒绝继续，提示先登出
- 登录后流程异常 → 以异常类型登出结束会话释放占用
- 登出失败 → 由实现侧重试，仍失败则等待超时后由调度器兜底
