# 03 · 鉴权体系

本文描述业务 API 通道的身份体系：机台如何证明自己是机台、玩家二维码如何兑换成会话身份。

## 一、身份体系总览

| 身份 | 载体 | 用途 |
|---|---|---|
| 机台身份 | keychip（机台芯片 ID） | 机台级请求的身份标识与签名素材 |
| 玩家身份 | userID + token | 二维码兑换所得，玩家级请求的会话凭证 |
| 游戏标识 | openGameID = `MAID` | 标识"舞萌 DX"游戏 |

## 二、二维码鉴权流程

玩家在官方手机端生成二维码，机台扫描后向鉴权库兑换身份。二维码以固定前缀开头（`SGWCMAID`，8 字节），随后是 12 位时间戳（共 20 字节的引导段），剩余部分才是有效载荷。

伪代码描述：

```
输入: 完整二维码文本 qr、机台 chipID

有效载荷 = qr[20:]                          # 当 qr 以 "SGWCMAID" 开头时截去前 20 字节
时间戳   = 当前北京时间，格式 YYMMDDHHMMSS
签名     = SHA256(chipID + 时间戳 + 鉴权盐).十六进制.大写()
              # 鉴权盐为固定字符串，值不公开

请求:  POST 鉴权库接口（地址不公开）
       头: User-Agent = "WC_AIME_LIB", Content-Type = application/json
       体: {
             chipID:     机台芯片ID,
             openGameID: "MAID",
             key:       签名,
             qrCode:    有效载荷,
             timestamp: 时间戳
           }

响应:  { errorID, userID, token, ... }
成功条件: errorID == 0 且包含 userID
```

### errorID 语义

| errorID | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 二维码并非最新（提示检查输入） |
| 2 | 二维码已过期（提示重新生成） |
| 其他 | 鉴权拒绝 |

### 要点

- 签名素材为 `chipID + 时间戳 + 鉴权盐`，按 UTF-8 编码后 SHA-256，输出**大写**十六进制
- 时间戳精确到秒，北京时间（UTC+8），与二维码引导段内的时间戳相互印证
- 该通道为**明文 JSON**，不走业务 API 的 AES 加密（见 02）

## 三、keychip 机台凭据

机台凭据是业务通道的"机台身份证"，一组完整凭据包含：

| 字段 | 说明 |
|---|---|
| chipID / keychip ID | 机台芯片唯一标识 |
| regionId / regionName | 省/市编号与名称 |
| placeId / placeName | 门店编号与名称 |

- 机台级请求（未绑定玩家）以 keychip ID 作为 User-Agent 身份段
- 二维码鉴权的签名以 chipID 为素材
- 多机台场景下按玩家固定映射或轮询分配机台凭据（值均不公开）

## 四、token 的流转

1. 二维码鉴权成功 → 获得 `userID + token`
2. 后续登录请求携带 token 完成会话建立（见 05-会话生命周期）
3. 玩家级请求的 User-Agent 身份段切换为 `userId`

## 五、加密版本探测

不同机台代际使用不同加密参数组（见 08）。协议实现通过"先用最新参数组做一次玩家预览，观察其客户端版本字段"的方式探测应使用的代际：

```
尝试最新代加密参数 → 玩家预览接口 → 读取 lastRomVersion
  ├─ lastRomVersion >= 新代阈值 → 使用新代参数组（预览结果可直接复用）
  ├─ lastRomVersion <  新代阈值 → 使用旧代参数组（需重新预览）
  └─ 最新代不可用/失败      → 降级使用旧代参数组
```

这一探测机制使协议实现能同时服务新旧两代机台的玩家数据。
