# 06 · 数据模型

本文描述业务通道的核心数据结构：用户全量数据（UpsertUserAll）、游玩记录（playlog）、票务与万花筒数据。

## 一、用户全量数据（UpsertUserAll 结构）

`UpsertUserAllApi` 是核心写入端点，其请求体为嵌套大字典：

```
{
  userId,            # 玩家 ID
  playlogId,         # 游玩记录序号
  isEventMode,       # 是否活动模式
  isFreePlay,        # 是否免费游玩
  loginDateTime,     # 登录时刻
  userPlaylogList[], # 本次游玩的单曲记录列表
  upsertUserAll: {
    userData[],               # 基础档案（约 70 字段，固定字段顺序）
    userExtend[],             # 扩展数据
    userOption[],             # 偏好设置
    userRatingList,           # 单曲 Rating 明细
    userCharacterList,        # 角色列表（含等级/觉醒）
    userGhost,                # 幽灵数据
    userMapList,              # 地图
    userLoginBonusList,       # 登录奖励
    userItemList,             # 物品库存
    userMusicDetailList,      # 乐曲成绩明细
    userCourseList,           # 段位课程
    userChargeList,           # 票务
    userFavoriteList,         # 收藏
    userActivityList,         # 活动
    userMissionDataList,      # 任务
    userWeeklyData,           # 周常
    userGamePlaylogList,      # 历史游玩记录
    user2pPlaylog,            # 双人游玩记录
    userIntimateList,         # 亲密度
    userShopItemStockList,    # 商店库存
    userGetPointList,         # 点数
    userTradeItemList,        # 交换物品
    userFavoritemusicList,    # 收藏乐曲
    userKaleidxScopeList,     # 万花筒之门
    isNewCharacterList,       # 新条目标志串（见下）
    isNewItemList,
    isNewMusicDetailList,
    ...                        # 其余各列表对应的 isNew* 标志串
  }
}
```

### isNew* 标志串

各列表伴随一条等长的 `"0"/"1"` 字符串，逐位标记对应下标元素是否为**本次新增**（"拆门式增量"）：服务端依据标志串区分"新增条目"与"存量条目"，只对新增部分做插入处理。构造方式是旧列表与新列表做差集后按新列表顺序生成标志。

## 二、游玩记录（playlog）

单条游玩记录包含五类键位 × 五档判定的 25 项计数，以及成绩与状态字段：

| 分组 | 字段 |
|---|---|
| 身份 | userId, orderId, playlogId, version |
| 机台 | placeId, placeName, clientId |
| 时间 | loginDate, playDate, userPlayDate |
| 曲目 | musicId, level, trackNo, type |
| 对战 | vsMode, vsUserName, vsStatus, vsUserRating, vsUserAchievement, vsUserGradeRank, vsRank, playerNum |
| 队友 | playedUserId1~3, playedUserName1~3, playedMusicLevel1~3 |
| 角色 | characterId1~5, characterLevel1~5, characterAwakening1~5 |
| 判定计数 | tap/hold/slide/touch/break × CriticalPerfect/Perfect/Great/Good/Miss（25 项） |
| 派生标志 | isTap, isHold, isSlide, isTouch, isBreak（本曲是否含该类键位） |
| 成绩 | achievement, deluxscore, scoreRank, maxCombo, totalCombo, maxSync, totalSync |
| 状态 | comboStatus, syncStatus, isClear（achievement ≥ 800000） |
| 偏移 | fastCount, lateCount（FAST/LATE 计数） |
| Rating | beforeRating, afterRating, beforeGrade, afterGrade, afterGradeRank, beforeDeluxRating, afterDeluxRating |
| 新纪录 | isAchieveNewRecord, isDeluxscoreNewRecord |
| 模式 | isPlayTutorial, isEventMode, isFreedomMode, playMode, isNewFree, trialPlayAchievement |
| 扩展 | extNum1, extNum2, extNum4, extBool1, extBool2 |

### 乐曲成绩明细（musicDetail）

`userMusicDetailList` 中每条成绩的最小字段集：

```
musicId, level, playCount, achievement,
comboStatus, syncStatus, deluxscoreMax, scoreRank, extNum1
```

### comboStatus / syncStatus 语义

| comboStatus | 含义 | syncStatus | 含义 |
|---|---|---|---|
| 0 | 无 | 0 | 无 |
| 1 | FC | 1 | FS |
| 2 | FC+ | 2 | FS+ |
| 3 | AP | 3 | FSD |
| 4 | AP+ | 4 | FS+ 更高档 |
| | | 5 | 同步 |

## 三、musicId 编号规则

- 标准曲目：每个 ID 对应一首歌的一个谱面池
- **DX 谱面**：DX 版曲目 ID = 原曲 ID + 10000
- **宴会场曲目**：ID 大于 100000
- 从社区数据源同步时需按上述规则做 ID 归一化（DX 曲目 `% 10000` 还原原曲 ID）

## 四、票务数据（charge）

### 读取（GetUserChargeApi 响应）

```
userChargeList: [ { chargeId, stock, purchaseDate, validDate } ]
userChargelog: [ { chargeId, price, purchaseDate, playCount,
                   playerRating, placeId, regionId, clientId } ]
```

### 写入（UpsertUserChargelogApi）

```
{
  userId, loginDateTime,
  userChargelog: { chargeId, price, purchaseDate, playCount,
                   playerRating, placeId, regionId, clientId },
  userCharge:    { chargeId, stock, purchaseDate, validDate }
}
```

- chargeId 与倍率对应：收费票 2~5 倍（chargeId 2/3/4/5，price = 倍率 - 1），另有免费票 ID（如 11001、30002、30003）
- validDate 计算：购买时刻减 4 小时再加 90 天，且时间部分固定为凌晨 4 点

## 五、万花筒之门（KaleidxScope）

`userKaleidxScopeList` 条目字段：

```
gateId,               # 门 ID
isGateFound,          # 是否发现门
isKeyFound,           # 是否获得钥匙
isClear,              # 是否通关
totalRestLife,        # 累计剩余生命
totalAchievement,     # 累计达成率
totalDeluxscore,      # 累计 DX 分
bestAchievement,      # 最佳达成率
bestDeluxscore,       # 最佳 DX 分
playCount             # 游玩次数
```

写入时仅修改目标门的 `isGateFound / isKeyFound` 等目标字段，其余条目原样回传。

## 六、字段顺序与默认值约定

- `userData` 的字段有**固定顺序**（约 70 个），构造时必须按序排布，缺失字段补默认值（数值 0、字符串空）
- 日期字段常见 `.0` 后缀（毫秒位）与特定时区表达，构造时需与原值格式一致
- 存档游戏 ID 等标识字段有强制取值（如国服存档标识），构造时不得随意更改
