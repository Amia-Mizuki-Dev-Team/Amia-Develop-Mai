# Amia-Develop-Mai

舞萌（maimai DX）**协议分析与开发文档**公开仓库，隶属 **Amia-Mizuki-Dev-Team**，面向**公共开发者**：只讲清流程、只给思路，**不公开任何可复现的凭据**（服务器地址、密钥、接口名称与构造细节均已隐去）。

## 内容汇总

### 舞萌国服通信体系分为四个部分

```
┌─────────────────────────────────────────────┐
│                官方服务器群                   │
│  A. 业务 API（游戏数据 Servlet）              │
│  B. 鉴权库（二维码 → 玩家身份）               │
│  C. 更新分发（ALL.Net）                      │
└──────┬──────────────────────┬───────────────┘
       │                      │
   ┌───┴───┐              ┌───┴────────────┐
   │ 街机机台 │              │ 社区查分平台     │
   └───────┘              │ (落雪/水鱼等)   │
                          └────────────────┘
```

| 通道 | 干什么 | 详见 |
|---|---|---|
| A. 业务 API | 玩家数据读写：登录/登出、成绩、物品、票务等 | [02](docs/02-传输与加密.md) [03](docs/03-鉴权体系.md) [04](docs/04-会话生命周期.md) |
| B. 鉴权库 | 机台扫描二维码，换取玩家身份凭证 | [03](docs/03-鉴权体系.md) |
| C. 更新分发 | 机台获取更新指示书、下载并解密更新包（游戏静态数据） | [06](docs/06-更新分发通道.md) |
| 第三方平台 | 社区查分平台 OAuth 授权与成绩接口 | [07](docs/07-第三方平台对接.md) |

### 一次业务会话的完整流程

```
机台初始化 → 二维码鉴权 → 登录前预检（占用检查+版本探测）
  → 建立会话（支持续关） → 拉取数据（单次类 + 游标分页）
  → 写入数据（全量同步/游玩记录/票务） → 登出（三次登出 + 性能统计）
```

### 核心机制一览

| 机制 | 一句话说明 | 详见 |
|---|---|---|
| 加密流水线 | 请求体 = AES-CBC(zlib(紧凑 JSON))，PKCS7 填充 | [02](docs/02-传输与加密.md) |
| 端点混淆 | URL 路径 = 接口名经哈希变换，抓包无法直接读出语义 | [02](docs/02-传输与加密.md) |
| 二维码鉴权 | 机台签名（SHA-256）→ 换取玩家身份凭证 | [03](docs/03-鉴权体系.md) |
| 游标分页 | 大数据量接口按"游标 + 每页条数"分页拉取 | [04](docs/04-会话生命周期.md) |
| 三次登出 | 连续多次登出请求，降低"假登录占用"概率 | [04](docs/04-会话生命周期.md) |
| 加密代际 | 参数组随客户端版本轮换，会话前自动探测代际 | [05](docs/05-加密版本代际.md) |
| 更新分发 | 指示书 → 断点续传/分块下载 → 专用工具解密出游戏 XML | [06](docs/06-更新分发通道.md) |

### 公开业务知识

- **DX Rating**：单曲 Rating = floor(定数 × 达成率/100 × 评级系数)；B50 即最佳 50 首之和（[08](docs/08-附录.md)）
- 达成率、难度档位、术语表等见 [08](docs/08-附录.md)
